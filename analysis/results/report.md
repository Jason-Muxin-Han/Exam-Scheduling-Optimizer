# Exam Scheduling Heuristic Comparison

Generated by `npm run experiment`. All numbers below are computed from the committed `experiment.csv`; nothing is hard-coded.

## Setup

- Instances: 96 (24 seeds x 4 problem sizes).
- Subject counts: 20, 30, 40, 50.
- Days per instance: ceil(N / 4) + 1, giving 4 * days available time slots.
- Minimum rest between two exams sharing a student: 30 minutes.
- Every instance uses the same seeded generator, the same conflict graph and the same constraint oracle for all three heuristics.
- Mean number of conflict edges per instance: 414.7.

## Conclusions derived from the data

1. Over 96 instances, course-order first-fit used 15.65 slots on average, while highest-conflict-first (Welsh-Powell ordering) used 14.91 (4.73% fewer slots).
2. DSATUR used 14.48 slots on average, i.e. 7.46% fewer than course order.
3. Slot-count wins (ties counted for each winner): Course order 20, Highest conflict first 57, DSATUR 89 out of 96 instances each.
4. Reordering subjects by conflict degree costs almost nothing: mean constraint evaluations went from 356 to 361 (+1.55%), while the slot count fell. Highly connected compulsory exams are placed earlier, leaving more reusable slots for electives.
5. All three heuristics are greedy and bounded by N * C constraint evaluations; none of them guarantees the chromatic number chi(G). A larger difference appears on sparse graphs, while dense graphs force every heuristic towards one slot per exam.

## Reproducing

```sh
npm test
npm run experiment
```

The generator uses a seeded mulberry32 PRNG and never reads the clock, so two consecutive runs produce byte-identical `experiment.csv`.
